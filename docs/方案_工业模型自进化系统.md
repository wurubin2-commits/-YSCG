# “智训引擎”工业制造场景下的模型训练与超参数优化 —— 参赛实施方案

> 赛事：第二届北京市大学生“人工智能+”创新大赛；赛题：“智训引擎”—工业制造场景下的模型训练与超参数优化；命题企业：软通计算机有限公司、华为技术有限公司
> 适用对象：本校校内选拔 → 企业选拔赛（线上客观评测 + 前 20 名线下答辩）→ 北京市线下总决赛
> 版本：v0.1（基于赛题规则 PDF；《实验记录规范》、官方数据包、评测 SDK 开放后需迭代对齐，文中标注【待确认】项）

## 0. 一句话方案

**做一个可离线自包含、无人干预运行的“工业模型自进化系统”：以确定性规则状态机保底实现“漂移监测—诊断归因—实验优化—评估上线—回滚”完整闭环（先守住三项门槛），模型层用模型池 + 受限预算超参优化实现自迭代，策略层用“规则决策 + 开发期 LLM Harness 建议、评测期固化离线”实现受控 RSI（递归自改进）；用最小算力 / 标注 / Token 换最大稳健增益，全部实验按规范写入 SwanLab 云端。**

类比：系统像一条“带体检和自动会诊的产线老师傅”——平时盯表值班，发现参数漂移先查原因，证据充分且划算才调模换代，新版先影子试用、达标再上岗，出问题立刻退回老师傅版本，全程记账留档。

## 1. 赛题拆解：规则要求 → 设计目标

### 1.1 任务实质
官方在漂移数据流上持续评测系统；公开训练集 / 验证集（含标签）与评测脚本公开，隐藏测试流不公开；系统须**无人工干预自主运行**，自动维持并提升模型性能，鼓励“**模型层自迭代 + 策略层自改进**”两层自进化（受控 RSI）。

### 1.2 三项基础门槛（不满足不进排名，最高优先级）

| 门槛（规则原文要点） | 对应设计保证 |
|---|---|
| ① 封闭评测中无人工干预完成全部阶段并按时输出结果 | 主流程为单一状态机驱动的可执行程序；异常熔断、超时兜底、默认输出当前最佳模型预测；镜像离线自包含、不依赖人工操作步骤 |
| ② 全部训练 / 微调 / 调整 / 评估实验按《实验记录规范》在云端完整记录 | 统一封装实验基类，自动落 SwanLab；每次更新 / 超参试验 / 回滚都强制一条 run；提交前做记录完整性 checklist |
| ③ 封闭评测综合性能不低于组委会静态基线（部署后不再更新的模型） | 模型池永久保留冻结基线（frozen baseline）作为下限对照；准入闸门要求新模型不劣于基线；极端情况回退到基线，保证不跌破门槛 |

### 1.3 评分构成反推设计策略

**客观分（平台自动计算）**：考察“**单位增益消耗**的算力（GPU 时长 / 训练额度）、标注配额、大模型 Token”。
→ 核心优化目标不是“盲目追求最高分”，而是**增益 / 成本 性价比**：默认不更新，证据强且划算才更新；优先 CPU 低成本模型；更新次数、标注条数、LLM 调用次数设硬预算；每次实验记录成本账本。

**主观分（专家评审）**：方法设计与技术路线、实验规范与分析深度、安全可控与工业落地、报告与答辩。
→ 需要：清晰技术路线论证文档、规范对照实验与消融、成本—收益分析表、受控安全机制说明、可演示闭环、答辩材料；亮点落在“两层自进化 + 成本受控 + 可落地”。

### 1.4 关键约束（设计红线）
- Python 3.10+；框架 / 跟踪工具 / 智能体框架不限；数据包规模小、提供预提取特征，**基础任务普通 CPU 可完成**。
- **正式评测为统一离线环境**：系统镜像须离线可跑、可复现、不得依赖评测期联网或外部未授权网络访问；提交的 Harness 大模型须来自 PyTRiO 训练模型或 PyTRiO 的 Qwen3.8-27B【型号以官方答疑为准】。
- PyTRiO 训推额度**仅企业赛提供**，校选赛无额度 → 校选阶段用规则 / 小模型打通，不依赖大模型。
- 禁止获取隐藏测试集、禁止攻击平台；系统须有受控机制防无限迭代；原创、开源许可合规。

## 2. 技术路线选择与论证

### 2.1 三条可选路线对比

| 路线 | 做法 | 优点 | 缺点 / 风险 | 结论 |
|---|---|---|---|---|
| A 纯静态基线（不更新） | 训练一个模型冻结后直接评测 | 成本最低、零失败风险 | 无法应对漂移，必然不满足门槛③上限与自进化考察，主观分低 | 仅作**保底对照基线**，不作主方案 |
| B 纯规则 / 传统持续微调 | 漂移阈值触发重训 / 增量更新，规则决策 | 离线稳定、CPU 友好、成本可控、完全可复现、易过门槛 | 策略自适应弱、缺少 LLM 亮点、主观分上限一般 | **保底主干（必做）** |
| C 纯 LLM Agent 驱动 | 大模型自主读记录、写代码、调参、决策 | 创新性强、主观分亮点高 | 客观分成本（Token/算力）高；离线评测下无法联网调用；小数据上易乱调不稳定；开发期无额度 | **不单独使用** |
| **D 混合分层（推荐）** | L0 规则状态机保底 + L1 模型层自迭代 + L2 策略层规则化自改进（开发期 LLM 辅助、评测期固化） | 兼顾达标、成本、稳定性与创新亮点；离线可跑；可降级 | 架构稍复杂，需做好模块边界与预算闸门 | **主方案** |

### 2.2 推荐路线 D 的分层结构

- **L0 确定性主干（规则状态机）**：数据流读取 → 监测 → 决策 → 训练 / 更新 → 影子评估 → 上线 / 回滚，全部由规则与确定性代码完成，保证无人干预、离线、低成本、可复现。
- **L1 模型层自迭代**：模型池（冻结基线 + 轻量树模型 + 轻量神经网络）；漂移触发后做增量更新 / 重训 / 超参微调；新旧模型在固定验证切片上对照，胜者上线；模型版本化入库。
- **L2 策略层自改进（受控 RSI）**：决策策略（触发阈值、更新冷却期、搜索空间大小、更新频率、标注预算分配、模型选择偏好）作为**版本化对象**；用历史实验回放（replay）和小规模对照不断优化策略版本；开发期（企业赛拿到额度后）用 Harness + LLM 阅读实验记录、提出策略 / 超参建议并生成实验配置；**评测前将有效策略固化为离线决策规则 / 小决策器**，镜像内不依赖在线 LLM。

### 2.3 为什么这样取舍（答辩口径）
1. 客观分给“成本效率”，纯 LLM 探索在 Token 与算力上不划算；
2. 评测离线，任何评测期联网 LLM 调用都不可用，策略必须能离线固化；
3. 数据量小、CPU 为主，重型深度模型收益有限、成本偏高；
4. 规则主干保证三项门槛，LLM 层只做增量亮点，失败可摘除不影响达标，风险可控；
5. 两层结构直接回应赛题“模型层 + 策略层”要求，便于主观分叙事。

## 3. 系统架构：五环节闭环 + 横切机制

### 3.1 闭环主流程（对应规则点名的五环节）

```
                       ┌──────────────── 策略层自改进(L2, 离线固化) ────────────────┐
                       │  历史实验回放 · 策略版本迭代 · 开发期 LLM Harness 建议      │
                       └───────────────┬─────────────────────────────────────────────┘
                                        │ 产出/调整策略参数与搜索空间
   隐藏测试流(评测,无标签) / 公开验证流(开发,含标签)
        │
        ▼
 [1] 漂移监测 monitor ──► 漂移等级(正常/预警/触发) + 漂移特征 + 统计量证据
        │
        ▼
 [2] 诊断归因 diagnose ──► 类型判定: 协变量漂移/概念漂移/噪声突发; 定位特征·工况·时段
        │
        ▼
 [3] 策略决策 policy(成本闸门) ──► 动作: 维持/增量更新/重训/超参微调/融合/申请标注/回滚
        │                         预算: GPU时长·标注条数·Token·迭代次数 硬上限
        ▼
 [4] 实验优化 optimize(模型层 L1) ──► 模型池候选训练 · 受限超参搜索 · 对照实验 · 成本账本
        │
        ▼
 [5] 评估上线 deploy ──► 影子评估 → 准入闸门(≥基线且不劣化) → 版本登记 → 灰度/主备切换
        │
        ├── 不达标/劣化 ──► [6] 回滚 rollback ──► 退回上一稳定版/冻结基线; 记录原因与成本
        │
        ▼
   持续回流到 [1]；每次事件写入 SwanLab 云端
```

### 3.2 模块职责明细

**（1）漂移监测 monitor**
- 协变量漂移（输入 X 分布变）：滚动窗口 PSI、单特征 KS / Wasserstein、多变量距离（MMD 或集成特征汇总），输出漂移指数与 Top 漂移特征。
- 概念漂移（X→y 关系变）：有标签窗口内滚动性能衰减；无标签运行时用残差分布偏移、预测置信度 / 集成方差 / 校准误差做代理信号。
- 变点检测：Page-Hinkley / ADWIN / DDM 类时序变点统计；区分缓漂移与突漂移。
- 输出统一结构化事件：时间窗、漂移类型信号、强度等级、涉及特征、证据数值。

**（2）诊断归因 diagnose**
- 类型判别：“X 分布变但残差关系稳定”多为协变量漂移；“残差系统性偏移 / 性能下滑”指向概念漂移；突跳且无分布变化关注噪声 / 异常工况。
- 定位：特征级贡献、样本切片（工况 / 类别 / 区间）、时段；关联当前模型版本与历史 run。
- 产出归因结论（结构化字段 + 简短文本），作为决策依据并写入 SwanLab；不做无证据的强行解释。

**（3）策略决策 policy（成本闸门，L2 载体）**
- 是否更新：综合劣化幅度、漂移证据强度、距上次更新冷却期、预算剩余、预期增益估计、历史更新性价比；**默认“维持”**，证据充分且预算允许才触发更新。
- 动作选择：维持 / 增量更新 / 全量重训 / 超参微调 / 模型融合 / 主动学习申请标注 / 回滚。
- 硬约束：最大更新次数、单次训练 GPU 时长上限、标注条数上限、LLM Token 预算、连续更新冷却期；超预算即拒绝并记录。
- 策略参数（阈值、权重、搜索范围、预算分配）版本化，随回放迭代升级，形成策略层自改进。

**（4）实验优化 optimize（模型层 L1）**
- 模型池：冻结基线（规则/轻量模型，永不被淘汰为最后保障）；LightGBM / XGBoost / 随机森林（CPU 友好、契合小数据）；可选轻量 MLP；必要时融合。
- 超参优化：Optuna（TPE）或等价贝叶斯搜索，**限定 trial 数量与时间**；每个 trial 记录配置、指标、成本；小数据先用网格 / 随机搜索兜底。
- 对照实验：候选模型与当前线上模型在**固定 held-out 切片**上 A/B，报告指标差、置信区间 / 显著性，避免“换了随机种子以为变好”。
- 训练数据切片管理：只用允许使用的数据与窗口；标注样本按主动学习准则挑高不确定 / 高价值样本，节省标注配额。

**（5）评估上线 deploy**
- 影子模式：新模型并行预测但不生效，比较与线上模型差异；
- 准入闸门：性能不低于基线与当前模型、预测分布合理、异常预测占比低于阈值、成本在预算内；
- 版本登记（模型卡）：版本号、指标、训练数据切片、超参、父版本、SwanLab run 链接、成本记录、时间戳；
- 上线：主备双模型 / 灰度切换，保留一键回退。

**（6）回滚 rollback + 熔断**
- 版本仓库保存模型权重、配置、模型卡；连续若干窗口劣化或跌破基线阈值自动回滚上一稳定版 / 冻结基线；
- 熔断条件：异常预测占比超限、成本超预算、训练 / 预测报错、输出格式非法；触发后切换安全模型并记录事件；
- 配合规则“重跑一次取较高成绩”，设计确定性种子与可复现流程，避免两次运行结果漂移。

### 3.3 横切机制
- **成本账本**：每次动作累计 GPU 秒 / 训练额度、标注条数、LLM Token、墙钟时间、训练次数；计算“增益 / 成本”，供客观分优化与答辩分析。
- **可观测性与记录**：统一 SwanLab 封装（见第 5 节）；本地缓存 `swanlog/` 忽略入库，云端为权威记录。
- **安全受控**：迭代次数上限、预算硬顶、网络调用默认关闭并集中封装、输出 schema 校验、禁止隐藏集访问、无外部不可控写操作。
- **离线可复现**：固定随机种子、锁定依赖、冻结数据快照、镜像内包含必要权重；评测环境无网络时仍能启动。

## 4. 模型与超参数优化设计（赛题副标题重点）

### 4.1 模型选型原则
小样本、预提取特征、CPU 可跑、要求低成本和可解释 → 以**树模型集成为主干**，线性 / 基线模型做下限对照，轻量神经网络作对比增强；不盲目堆叠大模型。

### 4.2 超参数优化策略（受预算约束）
1. 先确定搜索空间（浅层、保守范围），分模型定义空间（如学习率、最大深度、树数、叶子数、正则、子采样、网络宽度 / 层数）。
2. 分阶段搜索：随机搜索粗扫 → Optuna TPE 细调；trial 数与时长写入预算；每个 trial 计入成本账本。
3. 以“验证指标 + 成本”双目标记录，选帕累托较优点而非单纯最高分；防止在公开集上过拟合（留出时间切片验证 + 冻结基线对照）。
4. 策略层记录“哪些超参方向在历史上性价比高”，用于缩小后续搜索空间（策略自改进的具体落点之一）。

### 4.3 评估指标（待官方指标定义确认后锁定）【待确认】
- 分类（若为故障诊断 / 质检类别）：优先官方指定指标（如 F1 / 准确率 / AUC），辅以混淆矩阵、每类召回，兼顾误报漏报；
- 回归（若为质量值 / RUL 类）：MAE / RMSE / R²；
- 运行时另记漂移指数、更新次数、成本三项、增益成本比；所有指标以官方评测脚本为准。

## 5. SwanLab 云端实验记录落地方案（门槛②与提交资料②）

> 注意：正式实验必须用**云端 online 模式**（提交物需要“完整云端实验记录链接”）；本地 `mode="local"` 仅用于开发调试。

### 5.1 项目组织
- 云端项目沿用 `YSCG`；实验命名规范：`{模型}-{动作}-{版本}`，如 `lgbm-retrain-v03`、`optuna-trial-12`、`baseline-frozen`。
- `group`：按批次 / 赛段分组；`tags`：`baseline / update / ablation / optuna / policy / rollback / shadow`；`description` 写实验目的与结论。

### 5.2 必记内容（拿到《实验记录规范》后逐条对齐【待确认】）
- **config**：模型类型、全部超参、数据切片 / 窗口、漂移状态、策略版本号、父 run、成本预算、随机种子。
- **metrics**：官方性能指标（训练 / 验证 / 影子）、漂移指数、变点统计量、GPU 时长、标注条数、Token 数、增益成本比、更新 / 回滚事件计数。
- **媒体 artifacts**：漂移监测曲线、归因 / 特征贡献图、新旧模型对照曲线、残差 / 混淆图、模型卡摘要。
- **层级关系**：用 `parent` 思路在 description / config 中记录模型版本链与策略版本链，便于复盘“哪次更新带来多少增益、花了多少成本”。

### 5.3 提交前记录清单
- [ ] 每次训练 / 微调 / 超参试验 / 更新决策 / 回滚均有 run；
- [ ] config 与成本字段无空缺；
- [ ] 关键图表已上传；[ ] 记录链接可被评委公开访问（按规范设置可见性）；
- [ ] 整理一份“实验汇总表”（实验—目的—指标—成本—结论）作为答辩与分析附件。

## 6. 代码仓库结构与技术栈

### 6.1 推荐目录（当前仓库为初始化空仓，按此搭建）

```

├─ Dockerfile                     # 离线镜像：锁依赖、预装 wheel、禁用联网 pip
├─ configs/
│  ├─ data.yaml                  # 路径、窗口、切分规则

├─ data/                         # 公开训练/验证集（平台开放后放入；禁止放入隐藏集）
├─ src/
│  ├─ ingestion/                # 流式读取、时间窗口、特征预处理、切片
│  ├─ monitor/                  # 漂移检测、性能与不确定性监控、变点检测
│  ├─ diagnose/                 # 协变量/概念漂移判别、特征与工况归因
│  ├─ policy/                   # 决策规则、预算闸门、策略版本管理(L2)
│  ├─ modeling/                 # 模型池、训练/增量更新、模型卡、版本仓库
│  ├─ optimize/                 # Optuna/贝叶斯超参搜索、对照实验、融合

│  └─ common/                   # 日志、SwanLab 封装、随机种子、数据/模型序列化

├─ models_registry/             # 模型版本产物（大文件 gitignore，模型卡入库）
├─ docs/                        # 本方案、运行说明文档、技术路线论证、答辩材料
├─ tests/                       # 单元测试：决策闸门、回滚、成本计数、指标计算
├─ swanlog/                     # 本地缓存（.gitignore 忽略；云端为权威记录）
└─ scripts/                     # 一键训练基线、闭环主程序、打包镜像、记录校验脚本
```

### 6.2 技术栈建议
- 语言 / 运行时：Python 3.12（满足 ≥3.10；建议专用 conda 环境 `yscg`，避免污染全局环境）。
- 数据与数值：numpy、pandas、scipy、scikit-learn、joblib、PyYAML、pydantic。
- 模型：LightGBM、XGBoost、scikit-learn 集成模型；轻量 MLP（sklearn 或 PyTorch 小模型，按需）。
- 漂移 / 在线：river、scipy 统计检验；必要时 alibi-detect。
- 超参优化：Optuna（TPE，预算上限）；保留网格 / 随机搜索兜底。
- 实验记录：swanlab（云端 online 为正式，local 调试）。
- Agent / Harness：优先自研确定性状态机（可离线、可控）；开发期可接 LangGraph 等做编排探索；LLM 仅开发期建议、评测期固化。
- 部署 / 复现：Dockerfile + 锁定依赖 + 离线 wheel；输出统一 CLI 入口与配置化主程序。
- 文档：Markdown 运行说明 + 架构图；答辩阶段补 PPT（另按 PPT 规范制作）。

### 6.3 环境与依赖注意
- 先建专用环境再 `pip freeze`，避免把当前全局 228 个包写入项目依赖；
- 依赖锁定版本；评测离线，准备离线安装方案；
- 固定全部随机种子，数据快照可复现。

## 8. 风险、保底策略与合规清单

### 8.1 主要风险与对策
| 风险 | 对策 / 保底 |
|---|---|
| LLM 额度不足或模型不可用 | 规则驱动版完整保底，不依赖 LLM 也能闭环；LLM 为加分项 |
| 评测必须离线，不能联网调模型 | 策略离线固化；镜像自包含；网络默认关闭 |
| 小数据上过拟合、更新反而降分 | 保守更新阈值、冷却期、时间切片验证、冻结基线对照、宁可不更新 |
| 平台 / 数据 / 规范延期 | 先以合成数据打通管线，开放后替换；方案模块化低耦合 |
| 正式评测超时 / 报错被重跑 | 确定性流程、超时兜底、默认输出最佳模型、熔断保护、种子固定 |
| 客观分对成本敏感 | 默认维持、预算硬顶、低成本模型、精简 trial 数、Token 预算 |

### 8.2 安全合规（规则第四、（四）节）
- 不获取 / 不接触隐藏测试集，不攻击评测平台；
- 系统具备迭代上限与预算闸门，防止无限迭代；不植入恶意代码，不做未授权外联；
- 开源框架 / 预训练模型核对许可证；作品原创，引用留痕；账号妥善保管不外借。

### 8.3 提交物对照清单
1. 模型配置与 Harness 的系统镜像（离线可运行、含依赖锁定与启动说明）；
2. 完整云端实验记录链接（SwanLab，按规范可访问）；
3. 系统运行说明文档（环境、启动命令、闭环行为、版本与回滚说明、参数配置）；
4.（主观分支撑）技术路线论证、对照 / 消融实验、成本收益分析、答辩材料。
