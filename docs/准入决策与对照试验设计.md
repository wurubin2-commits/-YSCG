# 准入决策机制与对照试验设计（已落地）

> 状态：已实现（对应 `src/yscg` 的 `memory/`、`guardrails/anchor.py`、`guardrails/admission.py`、`guardrails/rollback.py`、`eval/control.py` 及 `pipeline/loop.py` 的接入）。

## 1. 需求 → 机制映射

| 需求 | 落地机制 | 代码位置 |
|---|---|---|
| 多层判断才接受候选 | 增益 → 锚点 → 记忆 三层门（AND） | `guardrails/admission.py` |
| 稳定性规则：锚点检查 | Anchor Gate：锚点分数单调不减、防能力退化 | `guardrails/anchor.py` |
| 稳定性规则：记忆检查 | Memory Gate：容量受限保护记录 + 分层回归样本 + 回归计数 ≤ 容差 | `memory/protective_memory.py` |
| 回滚不是免费的 | Rollback Guard：旧版本完整保留 + 回滚路径预演，通过才允许无干预上线 | `guardrails/rollback.py` |
| 对照试验防假象 | 对照组：相同算力/评估调用但不自我修改；报告方差与置信区间 | `eval/control.py` + `pipeline/loop.py` `control_mode` |
| 冻结留出任务作最终评判 | HeldOutSet：迭代不可访问，仅最终评分 | `eval/control.py` + `data/drift_sim.py` |
| 验证器失效则拒绝所有候选 | ValidatorProbe：已知好/坏候选排序自检 | `guardrails/admission.py` |
| 一次编译、多次廉价复用 | 回归样本按轮缓存复用；锚点/评估窗口冻结共享 | `memory` + `admission` 的 `round_key` |

## 2. 准入决策（稳定性规则）

```
候选 challenger
  │
  ├─ G1 增益检查：gain = win_acc(c) − win_acc(champion) ≥ promote_min_gain
  ├─ G2 锚点检查：每维 anchor_score ≥ floor − anchor_eps，且 floor 只升不降
  ├─ G3 记忆检查：分层回归样本上的硬回归计数 ≤ reg_tolerance_frac · |R|
  └─ 回滚护栏：旧版本完整保留 + 回滚预演一致（仅在上线前）
        │
   全部通过 → 准入（admission=pass）、promote、锚点 floor 抬升、记忆回写
   任一失败 → 归档（admission=fail）、champion 不变、记录失败原因码
```

- **锚点**：一组冻结、不可变、绝不参与训练的切片（当前用 val 集），跨版本可比；`floor` 为历史最优的单调棘轮，准入后才抬升。
- **记忆**：容量上限 `memory_capacity`；只收「分类正确且置信 ≥ memory_min_conf」的已标注样本；淘汰时去冗余（相似度最高者优先）。
- **回归样本**：保护记忆的分层采样，层 = `场景 × 难度 × 指标面`，每层保底 `memory_min_quota`，剩余按占比；同一轮（`round_key`）多个候选复用同一份样本。

## 3. 回滚护栏（回滚不是免费的）

上线前 `RollbackGuard.preflight(champion)`：
1. 冠军模型文件存在且非空（**完整保留**）；
2. 重载持久化冠军，与内存冠军在探针上预测一致（**回滚路径经过验证**）。

二者任一失败 → 以 `Gate.ROLLBACK` 拒绝上线，杜绝「上去了却退不回来」。

## 4. 对照试验

- **对照组**：与实验组从**完全相同初始工况**（同 seed、同 init/val/heldout 数据）出发，消耗**相同训练算力（模型拟合次数）与评估调用（标注条数）**（mock 顾问下 Token 两侧均为 0，天然对齐），但 `control_mode=True` 使其**永不 promote**——照常检测漂移、照常标注与重训，却丢弃挑战者、始终保留冻结基线。
- **报告**：`repeated_gain_report()` 输出每个 seed 的实验组/对照组留出分数、增益序列、`running`（n=1..N 的累计均值/标准差，即「观测方差随重复次数的关系」）与 `summary`（该 N 下增益的均值、标准差与 95% 置信区间，t 分布）。
- CLI：`python experiments/run_simulation.py --repeats 5 --control`

## 5. 冻结留出集

`TabularDriftSimulator` 新增 `heldout_samples` 独立切片，`get_heldout_data()` 供 `HeldOutSet` 使用；整个迭代（训练/验证/标注/HPO/锚点/记忆）都不接触它，仅在 `_final_summary` 里作 `summary/heldout_acc`。

## 6. 验证器自检

`ValidatorProbe(good, bad, pool)`：构造一次（compile once）好模型（轻量训练基线）与坏模型（多数类 `MajorityPredictor`），`healthy(gate)` 判断验证器能否对这对已知好/坏候选给出正确排序（好 > 坏）。若失效，`AdmissionGate.evaluate` 直接返回 `Gate.VALIDATOR`，**拒绝本轮所有候选**，并落 `validator/healthy=0`。

## 7. 成本与复用

- 锚点切片、评估窗口、回归样本在一次漂移事件内**冻结共享**，多候选并行验证时同一份样本只算一次预测。
- HPO 内所有 trial 复用一个 `score()`（验证集 + 池化窗口），不重复采样。
- 保护记忆淘汰去冗余，控制回归样本规模，验证成本不随历史样本线性膨胀。
