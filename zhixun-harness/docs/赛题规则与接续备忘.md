# 智训引擎｜赛题规则与接续备忘

规则与项目状态核对基准为 **2026-11-18**。接手开发、实验或汇报时，先读本页，再按文末链接核对官方规则、实现和原始证据。涉及提交或真实平台运行时，以当时的赛方规则页、作品提交页和官方 SDK 为准。

## 1. 项目目标与当前工作边界

- **首要目标是提高续训后工业模型的赛题评测表现。** A 优先提高 Macro-F1，准确率作参考。B 优先降低 RMSE，同时核对 MAE，单位为分钟。C 优先降低 RMSE，单位为循环，并按赛方口径参考 NASA 非对称评分。关注平均提升、最差阶段、恢复表现和稳定性。
- Harness 从赛方给出的工业模型检查点出发，读取当轮数据与历史，让获准的大模型提出续训建议，执行实验、比较效果，并自动采用候选或保留父模型。CPU、十轮、数据范围和 SDK 协议是实施约束。时间、Token、请求大小和训练次数是辅助指标，用于衡量提分的成本。
- **版本口径。** V1 为原始 Harness，V2 为 GitHub 的 `harness-integration-compact`（`df21cd2`），V3 为当前本地实验版，包含逐轮复盘及 A、B、C 的可选续训配方。V3 尚未发布到新分支，默认配置复现了 V2 的三项公开验证结果。已确认的收益局限于部分本地对照，三项整体提分仍未达成。
- 用户要求保留之前的研究成果，并对竞赛平台的上传和提交亲自操作。真实模型付费调用、平台试运行与正式测评须另获授权。GitHub 交付安排在代码收尾后，另建分支供队友审阅。
- 接续时先核对当前仓库的分支、状态和最新提交。有未提交改动时先识别来源并保留。每完成一个获准阶段，汇报实际变化、验证结果及未验证事项。

## 2. 赛题规则与工程约束

| 事项 | 核对口径 |
| --- | --- |
| 赛方任务 | A 气体识别为六类分类，Macro-F1 越高越好，参考准确率。B 轴承剩余寿命以分钟计，RMSE、MAE 越低越好。C 发动机剩余寿命以循环计，RMSE 越低越好，参考 NASA 非对称评分。 |
| 数据使用 | 公开数据集 A 包是三项任务各自的原始数据。对应三套 CPU 工业模型训练包提供任务说明、训练和验证投影、初始检查点与基线代码。按任务包和 SDK 合同核对数据与单位。B 任务采用轴承寿命回归。验证标签只供评估，训练只读当轮允许使用的训练数据。严禁使用隐藏测试标签或未来批次信息。 |
| 十轮优化 | 每个任务各十轮，从平台提供的检查点 CPU 续训。首轮读平台起点，后续读平台指定的父检查点。无人干预完成运行，完整记录过程，至少留下三次完整的「读历史 → 做实验 → 依据结果决策」记录，效果达到平台基线要求。 |
| 大模型与回执 | 通过赛方 SDK 网关调用获准的 PyTRiO 模型，参数量上限 27B，具体模型以作品提交页为准。每个正式轮次都要有本轮真实调用回执，包括保留父模型的轮次。PyTRiO Playground 当前选择只代表调试页配置。 |
| SDK | 已核对版本 `1.0.2`，协议 `contest.harness.workspace.v2`。入口模板为 `/app/harness.py`，参赛模块提供 `train(rnd)` 和 `predict(sample, model_dir)`。使用 SDK 读历史、父检查点与公开投影，登记候选，从 SDK 保存状态并结束轮次。预测标准输出遵循协议，诊断日志写标准错误。 |
| 容器资源 | 按 Linux/amd64、4 核 CPU、8 GB 内存、无 GPU、评测网络受限和根目录只读设计。依赖构建时装入，密钥由平台注入。宣讲提到约 2 GB 包体，提交前按平台实际计量口径核对。 |
| 评分 | 客观 35 分，平均性能提升 15、最差阶段与恢复速度 10、稳定性 5、资源效率 5。专家 65 分，方法设计 30、实验分析 15、安全与工业落地 10、报告与答辩 10。另有最高 10 分加分，总分封顶 100。 |
| 次数与材料 | 每队最多 10 次试运行，换作品版本也累计。正式评测最多 2 次，第二次须申请。材料包括镜像、源码、模型调用信息、实验记录链接、设计说明、技术报告（最多 10 页）、演示视频（最多 5 分钟）和来源声明。截止日期按学校公布。 |

## 3. 已完成的成果和待验证项

- 正式评测代码在 `zhixun-harness/stage2_official/`。沿用 `hxx` 的官方入口与续训流程，借鉴 `ZMC` 的实验去重和防退化设计。默认采用赛方标准 NumPy 续训，由当轮公开主指标决定是否采用候选。漂移、扩展配方、切片保护保留在研究模式。
- 现行项目策略为每轮一次模型请求、最多一个候选、输出上限 192 Token，并在训练前按任务、父检查点、训练数据、随机种子与生效参数去重。完整日志通过允许的状态机制保留，发给模型的反馈最多三条。候选与父模型必须在当轮可比较的口径下评估。相同、变差、失败或不可比较时保留父模型。
- 本地 Linux 容器已完成三任务各十轮的模拟宿主演练。已有 25 项测试通过。2026-11-17 同条件复跑中，旧 `hxx` 和整合版的三项最终检查点摘要各自相同。A 为 Macro-F1 **0.7368**，B 为 RMSE **570.76 分钟**，C 为 RMSE **51.83 循环**。A 采用候选 7 轮，B、C 各采用 3 轮。
- 正常分批时，模型消息正文由 56,687 降至 27,365 字节，少约 52%，总耗时接近。在人为设置的重复批次情景，训练和候选提交各由 18 次降至 9 次。这两组演练使用真实 CPU 训练和模拟大模型建议。实际 Token 用量、真实网关决策质量、正式平台运行与隐藏测试成绩仍待验证。

## 4. 第三版优化记录

### 早期方案与来源

1. **借鉴 River，先还原三任务十轮表现。** 用已有回执整理当轮父模型、候选与最终选择的公开指标，绘制同轮同验证数据上的差值，列出候选未采用的原因及耗时。优先核查 B 的七次保留。有可比参照和退化事件时，再统计恢复轮数。先判断差距来自训练更新、批次变化还是其他原因。 [River 顺序评估源码](https://github.com/online-ml/river/blob/main/river/evaluate/progressive_validation.py)
2. **借鉴 Transfer Learning Library，先对 B 试验父模型约束 L2-SP。** B 的早先研究配方让低剩余寿命样本的 MAE 从约 436 降到 335 分钟，同时整体 RMSE 从约 571 升到 598 分钟。新方案用现有 NumPy 在可选配方内约束权重偏离当轮父模型的幅度。冻结父权重作为参照，沿用检查点的模型格式、Adam 状态和归一化。先验证强度为零能复现现行标准训练，再锁定一个非零强度，做同起点、同批次、同种子、同学习率和同训练预算的配对对照。第一步更新时约束梯度为零，先核查哪些训练轮次确有多次参数更新。记录实际配方版本与强度，纳入训练去重键。 [L2-SP 实现](https://github.com/thuml/Transfer-Learning-Library/blob/master/tllib/regularization/delta.py) · [论文](https://arxiv.org/abs/1802.01483)
3. **先复核 B，再决定是否扩展到 A、C。** 使用预先留出的允许使用的公开批次，核对 B 整体 RMSE、MAE、最差阶段、低剩余寿命误差及资源开销。整体指标可复现改善，或在整体无退化时最差阶段有明确收益，再考虑扩展。只有局部收益或结果波动时，留作研究记录。真实平台验证单独安排。

当前按小预算逐项验证。历史中的不同父模型、训练批次、验证投影或评估口径都可能影响分数，给模型汇报时按证据范围描述，避免把差异直接归因到某个超参数。Optuna 搜索、逐 epoch 剪枝和全套开源框架接入目前列为备选。采用外部代码时记录版本、许可证和来源，竞赛容器优先复用现有依赖。 [开源策略调研笔记](reports/早期配方源码调研.md)

### 已实施和实测结果

- 第一阶段已从 `hxx` 和整合版回放中逐轮核对 60 条记录，交付 Markdown、CSV 和曲线。B 的七次保留全部由候选 RMSE 升高触发，当轮回退保护了已选模型。 [十轮回顾](reports/旧版十轮回顾.md)
- 第二阶段在 B 接入可选 L2-SP。Windows CPU 公开数据配对回放中，标准续训到 L2-SP 的最终 RMSE 为 570.76 → 572.26 分钟，整体 MAE 为 463.95 → 466.51 分钟，低寿命 MAE 为 435.95 → 424.92 分钟。两组各十轮且各采用三个候选。整体误差上升，L2-SP 保留为实验选项。 [对照命令和结果](../README.md#b-轴承任务的-l2-sp-对照)
- V2 与 V3 默认配置的 A、B、C 各跑十轮。逐轮候选和最终检查点均一致，A 的 Macro-F1 为 0.7368、准确率为 88.83%，B 的 RMSE / MAE 为 570.76 / 463.95 分钟，C 的 RMSE / MAE 为 51.83 / 38.02 循环。请求正文均为 27,365 字节，总耗时分别为 115.92 和 117.54 秒，属于单次本机测量。 [两版复跑报告](reports/版本实跑对比.md)
- 最新提分实验中，A 尝试放大、缩小和固定学习率，最高公开 Macro-F1 仍为 0.7368。B 的固定学习率和只训输出层等策略，在整份验证集与逐轴承留出验证上的表现不一致，暂未找到可稳定降误差的策略。
- C 已接入可选开关 `ZHIXUN_C_HALF_RATE=1`。官方 SDK 本地模拟十轮中，RMSE 从 **51.8281 降至 51.7725 循环**，约改善 **0.11%**，MAE 从 **38.0226 降至 37.7272 循环**。两组各训练、登记十个候选，各有十次模拟模型调用。三个按整台发动机留出的组 RMSE 均下降，但换序回放有一组 RMSE 从 51.64 升至 51.77。开关默认关闭。真实平台成绩和实际 Token 用量仍待验证。 [效果复核与运行记录](reports/学习率效果复核.md)

### A、B、C 单因素实验

- 已按《工业模型提分方案》完成第一段。以 V2 为对照，固定十轮数据摘要、种子和训练预算，复算 A 六类混淆矩阵、B 逐轴承及逐轮偏差、C 分子集误差，并登记候选比较表。 [第一段交付](reports/固定基线.md)
- 第二段 A 通道遮蔽已验证。16 组传感器列映射与赛方公开投影一致。标准组与遮蔽组的最终 Macro-F1 分别为 0.736778 和 0.728357，乙醛均为 0/109。第 7 轮同父配对的 Macro-F1 相同。保留标准默认与可复现的实验入口。 [第二段报告](reports/A通道遮蔽.md)
- 第三段 B 残差分解损失已完成。均值项权重为 1 时与标准 MSE 等价，固定 0.5 的十轮公开 RMSE 为 568.24 分钟，相对标准组 570.76 改善约 0.44%。整轴留出汇总 RMSE 从 686.70 升至 688.45，两根轴承退步，B 默认继续标准续训。 [第三段报告](reports/B残差损失.md)
- 第四段 C 工况分组损失已验证。标准、学习率减半、工况损失的公开 RMSE 分别为 51.8281、51.7725、51.8344 循环。工况组整机留出只有极小收益，减半组整份公开集的 NASA PHM’08 非对称参考分数升高。C 默认继续标准续训。此阶段项目测试 22 项通过，容器上下文清单核对通过。 [第四段报告](reports/C工况损失.md)

## 5. 最新 Harness 调研与接续任务

### 已核对的瓶颈

- V2 与 V3 默认回放逐轮复现同一候选检查点和采用结果，没有发现 SDK 接入或检查点续训出错的证据。当前回放的学习率和策略由模拟建议预设，能核验运行链路，真实模型选策略的能力仍待实测。每轮最多一个候选、全程最多 12 个 epoch 是项目当前策略。基准实际运行 10 个 epoch，A、B、C 分别执行 10、60、450 次梯度更新。
- A 的批大小从 128 调到 32 后，更新次数从 10 增至 20，Macro-F1 仍为 0.7368。按公开训练集类别频率做固定先验校正后，Macro-F1 降至 0.6740。两种方法的乙醛识别均为 0/109。以「乙醛 logit 减乙醇 logit」作二类排序，公开验证批次上的排序 AUC 从起点的 0.140 降至标准续训后的 0.102，表明起点已存在逆向排序。这些证据只覆盖一个公开验证批次。 [瓶颈分析与对照数据](reports/Harness瓶颈与整合建议.md)

### 接续顺序与验收

1. **先做 A 的传感器排查。** 定位哪些传感器组的乙醛、乙醇排序跨批次变化最大，再固定一种轻微的整通道幅度扰动，只用于当轮授权训练输入。先做同父检查点、同批、同种子、同预算的单因素对照。这是下一段的接续点，等待用户指示启动。
2. **把有效的方案送入完整十轮。** 借鉴 autoresearch 固定评分和预算的做法，以及 OpenEvolve 分级评估的做法。先看少量配对回合的六类 Macro-F1 和乙醛召回，再比较十轮平均、最差轮、最终主指标及资源开销。赛前对照复用现有训练器和模拟宿主，正式入口继续按官方 SDK 提交候选并依据宿主评分决策。 [开源源码核对](reports/Harness开源源码调研.md)
3. **用合规留出数据决定是否采用。** A 优先用独立气体批次，B 按整根轴承，C 按整台发动机，并检查换序稳定性。现有公开评估结果用于挑方案，按开发证据记录。验收优先看主指标能否稳定改善，再结合辅助指标、最差阶段和实际资源开销。正式隐藏集效果以平台结果为准。

GitHub 交付时按模块整理源码、入口、测试与说明，并检查暂存文件范围。
