# 提分方案第一段｜固定基线与错误诊断

依据 2026-11-18 的提分方案。使用 V2 `df21cd2` 与 V3 默认配置各三项十轮的已有回执、赛方公开投影和选中检查点。核对了两版 60 条轮次回执，以及用于复算的各任务初始检查点、每轮训练文件、验证文件和候选检查点摘要。两版同轮的父模型、输入、种子、生效超参数、候选和采用决定一致。诊断均为现有模型的本地 CPU 推理。 [提分方案](../工业模型提分方案.md) · [逐轮摘要与诊断数据](../results/baseline-rounds.json)

## 锁定的对照条件

- 从对应任务的赛方初始检查点开始，种子为 42。正常顺序采用十份已经存档并核验摘要的训练投影，逐轮读当时开放的训练数据。下一轮从各对照组实际采用的父检查点继续。
- 第一组十轮对照使用同一模拟建议，学习率按 0.001、0.0005、0.00075 循环。三任务各每轮一个训练候选、一轮训练一次遍历，A/B 批大小 128，C 批大小 256。机制实验另用同父同批配对，确保每次只改一个因素。模拟请求、候选提交、实际 epoch 和梯度更新数均计入对照。
- 同轮用相同验证投影比较父模型和候选。只在主指标改善且符合约束时采用，否则保留父模型。按**每轮结束实际选中的模型**计算十轮平均、最差轮及最终值。出现可比退步时记录恢复轮数。固定验证投影的既有回放中，所选模型的主指标单调，恢复轮数无适用事件。
- 公开开发验证组已用于提出方案。在新增合规留出组上评估时，先固定候选、监控组和评分组，评分组仅用于最终评分。A 用后到的完整气体批次，B 按整根轴承，C 按「子集＋机号」隔离整台发动机。A 的现有验证只覆盖一个来源批次，独立整批复核仍依赖赛方另行开放的合规输入。

## 复核方法

在 `zhixun-harness` 下用项目 Python 执行以下命令。输出文件名需为空闲名称。

```powershell
$env:OPENBLAS_NUM_THREADS = '1'
python -B evidence/score-improvement-stage1/audit.py diagnostic-repeat.json
```

本次使用 Python 3.12.10 和 NumPy 1.26.4 复算，三项最终主指标与既有 SDK 回执相符。新增产物均为本地诊断与比较口径。 复算代码（本地留档） · [已有回放对照](版本实跑对比.md)
